## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ถือว่าล้มเหลว

**เป้าหมาย**
- ทั้งแอปใช้ design system ชุดเดียว ในหน้าจอไม่มีสีฝัง hex เหลืออยู่เลย
- ช่างใช้งานกลางแจ้งได้: ตัวอักษรทุกคู่สีผ่าน contrast 4.5:1 และพื้นที่กดทุกจุดสูงอย่างน้อย 48dp
- เมนูด้านล่างปรับตาม role สลับไปมาระหว่างงาน อุปกรณ์ และแจ้งเตือนได้ในแตะเดียว
- เขียนทุกหน้าใหม่บนฐานเดียวกันทั้งหน้า ไม่แก้แบบปะผุทีละจุด

**ไม่ใช่เป้าหมาย**
- ไม่แก้ Backend และ Web ในรอบนี้
- ไม่เพิ่มฟีเจอร์ business ใหม่ ยกเว้น `activePartition` / `hardwareRevisionCode` บนหน้า Device Detail ที่ค้างจาก `docs/18` ข้อ 6
- ไม่มีปุ่มสแกน QR (B ตัดสิน 16 ต.ค. 2569 ดู §8 ข้อ 1)
- ไม่ทำหน้าตัดสินใจของ Operation บนมือถือ (มติ #303 ข้อ 3: ทำบนเว็บ)
- dark mode เก็บ `AppTheme.dark()` ไว้ให้ build ได้ แต่ไม่ลงแรงขัดเกลา

**ถือว่าล้มเหลว (แม้จะทำงานได้)**
- PR ก้อนเดียวใหญ่จนรีวิวไม่ได้
- ช่วงเปลี่ยนผ่านมี build พัง หรือเทส / E2E ต้องปิดไว้ชั่วคราว
- push notification deep link พาไปผิดหน้า หรือกด back แล้วหลุดออกจากแอป (regression ของ #331 ข้อ #4)
- ทำงานออฟไลน์แล้วฟอนต์ไทยกลายเป็นกล่องสี่เหลี่ยม

### 4.1 Design tokens

แนวทาง: **Clean, High-Contrast & Utilitarian Field Service**

| Token | ค่า | ใช้กับ |
|---|---|---|
| `primary` | `#2563EB` | ปุ่มหลัก ลิงก์ แท็บที่เลือก (ตัวอักษรขาวบนพื้นนี้ได้ 5.17:1) |
| `background` | `#F8FAFC` | พื้นหลังของแอป |
| `surface` | `#FFFFFF` | การ์ด |
| `border` | `#E2E8F0` (1px) | ขอบการ์ด เป็น**ของตกแต่ง** (1.23:1 บนพื้นขาว ไม่ต้องถึง 3:1) |
| `inputBorder` | `#64748B` | **ขอบช่องกรอกเท่านั้น** แยกจาก `border` เพราะเป็น UI component ที่ต้องถึง **3:1** ตาม WCAG 1.4.11 ได้ 4.76:1 บนพื้นขาว และ 4.55:1 บน background (#335 ใช้ token แยกแบบเดียวกันคือ `inputBorder` `#778DA4` ได้ 3.43:1) |

| `textSecondary` | `#475569` | label และข้อความรอง (7.58:1 บนพื้นขาว) |
| `textMuted` | `#94A3B8` | **ของตกแต่งเท่านั้น** เช่น placeholder หรือเส้นแบ่ง ห้ามใช้กับข้อความที่ต้องอ่าน (2.56:1) |

**สีสถานะ:** แต่ละ tone มี 3 ค่า ค่า `fg` เข้มกว่าที่ brief เสนอหนึ่งระดับ เพราะค่าใน brief ไม่ผ่าน 4.5:1

| Tone | `fg` (ข้อความ) | `icon` (ไอคอน/ขอบ) | `bg` (พื้น) | contrast ของ `fg` บน `bg` | ค่าใน brief บน `bg` |
|---|---|---|---|---|---|
| success | `#047857` | `#059669` | `#ECFDF5` | **5.21** ✅ | 3.58 ❌ |
| warning | `#B45309` | `#D97706` | `#FFFBEB` | **4.84** ✅ | 3.07 ❌ |
| danger | `#B91C1C` | `#DC2626` | `#FEF2F2` | **5.91** ✅ | 4.41 ❌ |
| neutral | `#475569` | `#64748B` | `#F1F5F9` | **6.92** ✅ | 4.34 ❌ |
| info | ใช้ `primary` | `primary` | ตัดสินตอน Step 1 | ต้องผ่าน 4.5 | — |

- **ตัวอักษร:** bundle ฟอนต์ **Noto Sans Thai** เป็น asset ในแอป (ไม่ใช้ `google_fonts` ที่โหลดจากเน็ต)
  - **license:** SIL Open Font License 1.1 วางไฟล์ `OFL.txt` ไว้คู่กับฟอนต์ใน `mobile/assets/fonts/` และลงทะเบียน
    ผ่าน `LicenseRegistry.addLicense` ให้ขึ้นในหน้า license ของแอป
  - **น้ำหนัก 3 ระดับ:** 400 (เนื้อหา), 500 (label และปุ่ม), 700 (หัวข้อและตัวเลขสำคัญ) ไม่ใส่ 600 หรือ 300
    เพื่อคุมขนาดแอป
  - **variable หรือ static:** ถ้าตรวจใน Step 1 แล้วว่า `TextStyle.fontWeight` ขับแกน `wght` ของ variable font ได้จริง
    ทั้ง Android และ iOS ให้ใช้ไฟล์ variable ไฟล์เดียว (เล็กกว่า) ถ้าไม่ได้ ให้ใช้ static 3 ไฟล์ ใน PR ของ Step 1
    ต้องรายงานขนาด APK ที่เพิ่มขึ้นเป็นตัวเลขจริง
  - ต้องตรวจใน Step 1 ด้วยว่าตัวละตินและตัวเลข (deviceId, IMEI, serial) มี glyph ครบ ถ้าไม่ครบให้ตั้ง
    `fontFamilyFallback` ไปที่ Noto Sans (OFL เหมือนกัน)
- **ขนาดกด:** ขั้นต่ำ 48dp ตั้งไว้ที่ระดับ theme (`materialTapTargetSize`, `minimumSize` ของปุ่ม)
- **โหมด:** โฟกัส light mode
- **จังหวะสลับ ThemeData ทั้งแอป: Step 5** ระหว่างทางใช้ theme ใหม่เฉพาะหน้าที่ย้ายแล้ว

    ทุกหน้าที่ย้ายแล้วครอบด้วย `Theme(data: AppTheme.v2())` ตอน Step 5 ค่อยสลับ `MaterialApp.theme` ทั้งแอปแล้ว

  - **เหตุผล:** ถ้าสลับทั้งแอปตั้งแต่ Step 1 หรือ 3 หน้าที่ยังไม่ย้าย (ซึ่งยังฝัง hex เก่า) จะได้ theme ใหม่ปนกับ

  - **ข้อเสีย:** ระหว่างทางมี ThemeData สองชุด จะลบชุดเก่าได้ก็ต่อเมื่อถึง Step 5 (ซึ่งเป็นงานของ Step 5 อยู่แล้ว)

  - ถึง Step 5 เทสสองไฟล์นี้ยังใช้ได้กับหน้าที่ยังไม่ย้าย จึงคงไว้ตามเดิม

### 4.3 แท็บด้านล่างตาม role

**ไม่รวม Home เข้ากับแท็บงาน** เพราะ Home ยังเป็น dashboard ภาพรวมและจุดรวมทางลัด

| Role | แท็บ |
|---|---|
| ST / OT | **หน้าหลัก** · **งาน** · **อุปกรณ์** · **แจ้งเตือน** |
| Operation | **หน้าหลัก** · **อุปกรณ์** · **แจ้งเตือน** · **เมนูอื่น ๆ** (ไม่มีแท็บงานเลย ไม่แสดงแท็บว่าง) |

- **role ที่ใช้ Mobile ได้มีแค่ ST / OT / Operation** Auditor กับ Admin ถูกบล็อกบน Mobile ตั้งแต่ #305 (มติ #303
  ข้อ 2) ส่วน SuperAdmin ถูกบล็อกที่หน้า login มาก่อนหน้านั้นแล้ว จึงไม่มีแท็บชุดไหนสำหรับสาม role นี้
- ใช้ `StatefulShellRoute` ของ go_router ให้แต่ละแท็บจำ stack กับตำแหน่งที่เลื่อนไว้
- หน้าย่อย (Task Detail, Device Detail, Override, Confirm Install, Field Report ฯลฯ) เปิดซ้อน**เต็มจอ ทับเมนู**

**จุดเสี่ยงของ Step 3 (จากรีวิวของ A) และวิธีรับมือ**
- **แท็บตาม role แต่ branch ตายตัว:** `StatefulShellRoute` กำหนด branch ตอนสร้าง router แต่แท็บของ ST/OT กับ
  Operation ต่างกัน และอุปกรณ์/แจ้งเตือนอยู่คนละลำดับ วิธีที่ใช้คือประกาศ branch ครบทุกตัว (หน้าหลัก, งาน,
  อุปกรณ์, แจ้งเตือน, เมนูอื่น ๆ) แล้วให้ `NavigationBar` แสดงเฉพาะแท็บของ role นั้น โดยแปลง index ของแท็บที่
  แสดงเป็น index ของ branch และใน `redirect` ถ้า role ที่ไม่มีแท็บนั้นเปิด `/tasks` (หรือเปิด `/more` ในฐานะ
  ST/OT) ให้ส่งกลับไปที่ `/home`
- **state ค้างข้ามผู้ใช้:** branch ของ shell เก็บ stack และตำแหน่งเลื่อนไว้ ถ้าคนแรก logout แล้วอีกคน login บน
  เครื่องเดิม หน้าและ state ของคนก่อนต้องไม่โผล่มา (logout ล้าง DB ในเครื่องอยู่แล้ว) ต้องสร้าง shell
  ใหม่เมื่อเปลี่ยนผู้ใช้ และ**มีเทสเฉพาะเรื่องนี้**
- **หน้าย่อยเต็มจอทับเมนู:** route ของหน้าย่อยทุกตัวต้องตั้ง `parentNavigatorKey` เป็น root navigator
- **เปิดแอปจากการแตะ push ตอนแอปปิดอยู่ (cold start):** กด back แล้วต้องกลับไปที่แท็บ ไม่ใช่ออกจากแอป ใช้
  **เทสแยกจากกรณีที่แอปเปิดอยู่**

## 9. ข้อตัดสินใจของผู้เขียน (ค้านได้)
