# Postman — วิธีใช้

มีไฟล์เดียว: **`ESP32-Management.postman_collection.json`**

> ทำแบบเดียวกันได้ทั้งหมดในหน้าเว็บ **http://localhost:3019/admin** (ง่ายกว่า) — Postman เหมาะกับการทดสอบ API / ให้โปรแกรมอื่นเรียกใช้

## เตรียม (ครั้งเดียว)
1. เปิด server: ดับเบิลคลิก `start-servers.bat`
2. Postman → **Import** → เลือก `ESP32-Management.postman_collection.json`
3. ถ้าเคย import ชุดเก่าไว้ ให้ลบ collection และ environment ชุดเก่าทิ้ง **และเลือก environment เป็น "No Environment"** (มุมขวาบน)

ไม่ต้องตั้งค่าอะไรเพิ่ม ตัวแปรอยู่ใน collection แล้ว (คลิกชื่อ collection → แท็บ **Variables**)

| ตัวแปร | ค่าเริ่มต้น | ใช้ทำอะไร |
|---|---|---|
| `device_id` | `BOX-0001` | กล่องที่จะจัดการ — เปลี่ยนเมื่อจัดการกล่องอื่น |
| `base_url` | `http://localhost:3019` | ที่อยู่ server — ระบบอื่นใช้ `http://192.168.1.100:3019` |
| `firmware_version` | `1.0.0` | เวอร์ชันของไฟล์ firmware ที่จะส่งให้กล่อง (ข้อ 3.1) |
| `admin_username` / `admin_password` | `admin` / `admin123` | ใช้ Login |
| `admin_token`, `config_version`, `command_id` | — | **ระบบใส่ให้เอง** ไม่ต้องแก้ |

## ลำดับการใช้งาน

```
0. เริ่มต้น       → Login (ทำครั้งแรกทุกครั้งที่เปิด Postman)
1. ดูข้อมูลกล่อง  → กล่องออนไลน์ไหม / เวอร์ชันอะไร / config ตรงไหม
2. ตั้ง Config    → เลือก 2.1–2.4 (กล่องได้รับทันที) → 2.6 ดูผล
3. Firmware       → 3.1 ส่งไฟล์ .bin ให้กล่อง (อัปเดตทันที) → 3.2 ดูความคืบหน้า
4. ประวัติ        → ประวัติคำสั่ง / ยกเลิกคำสั่ง / ระงับกล่อง
5. จำลองเป็นกล่อง → ใช้ทดสอบเมื่อไม่มีกล่องจริง
```

### 2. ตั้ง Config — เลือกให้ตรงกับ firmware ที่กล่องรันอยู่
| Request | ใช้กับ firmware | ผล |
|---|---|---|
| 2.1 ส่ง GPS ทุก 10 วินาที | 1.0.0 ขึ้นไป | config ปกติ |
| 2.2 ปิด LED | 1.0.0 ขึ้นไป | LED บนบอร์ดดับ (สาธิตได้ทันที) |
| 2.3 ความเร็วสูงสุด 80 | 1.1.0 ขึ้นไป | ถ้ากล่องยังเป็น 1.0.0 จะถูกปฏิเสธ (ถูกต้อง) |
| 2.4 ความเร็ว + Geofence | 1.2.0 | แก้ `center_lat` / `center_lng` เป็นพิกัดที่ต้องการ |
| 2.7 เปลี่ยนรอบส่ง GPS เป็น 20 วินาที | 1.0.0 ขึ้นไป | เปลี่ยนเฉพาะรอบส่ง คงค่าอื่น ใช้หลัง downgrade ได้ |
| 2.8 ประวัติ Config | ทุกเวอร์ชัน | ดู Config ปัจจุบันและค่าก่อนแก้ |

**กด 2.1–2.4 แล้วกล่องได้รับค่าใหม่ทันที** (Server บันทึกและสั่งกล่องให้เอง) แล้วกด 2.6 ดูผล — 2.5 ใช้เมื่อต้องการส่งซ้ำเท่านั้น (เปิด **Console** ด้านล่างของ Postman จะเห็นลำดับสถานะ)

ข้อ **2.2–2.4 และ 2.7** ส่งเฉพาะค่าที่ต้องการเปลี่ยน จึงคงค่า GPS / Data Server เดิมที่ไม่ได้ส่งมา ส่วน **2.1** เป็นตัวอย่าง Config เต็ม รวมปลายทางตัวอย่าง `data.example.com`

รอบส่งต้องอยู่ใต้ `gps` เช่น Body ของ **2.7**:

```json
{ "settings": { "gps": { "send_interval_sec": 20 } } }
```

หากส่ง `send_interval_sec` ตรงใต้ `settings` จะได้ `INVALID_CONFIG` พร้อมคำแนะนำให้ใช้ `gps.send_interval_sec`

**หลังย้อน firmware:** เช่น 1.2.0 → 1.0.0 ให้รอจนข้อมูลกล่องในโฟลเดอร์ 1 รายงาน firmware 1.0.0 / schema 1 แล้วใช้ **2.7** ค่า `speed_limit` และ `geofence` ที่ค้างใน Config เดิมจะถูกตัดเมื่อบันทึกครั้งถัดไป โดยเก็บ Config ก่อนแก้ไว้ใน **2.8** หากส่งค่าเหล่านี้เข้ามาใหม่บน firmware ที่ไม่รองรับ จะยังถูกปฏิเสธตามเดิม

### 3. Firmware — ส่งไฟล์ให้กล่องอัปเดตทันที
1. ตั้งตัวแปร `device_id` (กล่องที่จะอัปเดต) และ `firmware_version` (เวอร์ชันของไฟล์ เช่น `1.1.0`)
2. **3.1** → Body → **binary** → เลือกไฟล์ `.bin` → Send — **กล่องเริ่มอัปเดตทันที** ไม่ต้องอัปโหลดก่อน ไม่ต้องเซ็น
   - **ย้อนเวอร์ชัน (downgrade):** ใช้ **3.1b** แทน แล้วเลือกไฟล์เวอร์ชันเก่า (เช่น `esp32_gps_box-1.0.0.bin`) — กล่องจะติดตั้ง รีบูต และกลับมาเป็นเวอร์ชันเก่า
3. **3.2** กดซ้ำเพื่อดู `DOWNLOADING %` → `SUCCESS`

ขั้นสูง (ไม่จำเป็น):
- **3.4** ส่ง firmware เดียวกันให้หลายกล่อง (`deploy_to` = `BOX-0001,BOX-0002` หรือ `all`) หรือเก็บไฟล์ไว้ก่อนแล้วค่อยสั่งด้วย **3.5**
- **3.6** เพิ่ม Schema — เมื่อ firmware ใหม่มีค่าตั้งใหม่ (เช่น 1.1.0 เพิ่ม speed_limit) เพื่อให้ตั้ง Config ค่าใหม่ได้

> **ระบบอื่น (คนละเครื่อง)** ให้แก้ตัวแปร `base_url` เป็น `http://192.168.1.100:3019`

### รู้ผลสุดท้ายทันที (`wait_result`)
ตัวแปร `wait_result` = `true` (ค่าเริ่มต้น) → ข้อ 2.1–2.4, 2.7, 3.1, 3.1b จะ**รอจนกล่องทำเสร็จ**แล้วค่อยตอบ (สูงสุด 5 นาที) ผลตอบกลับมี `message` เช่น `อัปเดต firmware v1.1.0: สำเร็จ` หรือ `ไม่สำเร็จ: <สาเหตุ>` และ `result.steps` ลำดับขั้นตอนทั้งหมด
- สำเร็จ = HTTP 200/201 · ไม่สำเร็จ = HTTP 500 · ตั้ง `false` ถ้าต้องการให้ตอบทันทีแล้วไปดูผลที่ 2.6 / 3.2
- ระบบอื่นเรียก API เองให้ใส่ header `X-Wait-Result: true`

## ผลที่ไม่ใช่ error
| เห็นอะไร | ความหมาย |
|---|---|
| 2.1–2.4 ได้ `command.status = PENDING` | กล่องออฟไลน์ คำสั่งจะถูกส่งเองเมื่อกล่องออนไลน์ |
| 2.3 / 2.4 ได้ 400 หรือ 409 | firmware ในกล่องยังไม่รองรับค่านั้น — อัปเดต firmware ก่อน |
| 3.2 ได้ 409 `RELEASE_EXISTS` | เวอร์ชันนี้อยู่บน server แล้ว (ลบด้วย 3.6 ก่อนถ้าจะอัปโหลดทับ) |
| 3.2 ได้ 400 `UNKNOWN_SCHEMA` | ยังไม่มี schema นั้น → เพิ่มด้วย 3.3 หรือใช้ schema เดิม |
| 3.1 / 3.5 ได้ 409 `FIRMWARE_UPDATE_IN_PROGRESS` | มีงานอัปเดตค้างอยู่ รอให้เสร็จหรือยกเลิกก่อน |
| ทุกอย่างได้ 401 | ยังไม่ได้กด Login หรือเปิด server ใหม่ → กด **0. Login** อีกครั้ง |

## ทดสอบ WebSocket ด้วย Postman (ไม่จำเป็น)
New → WebSocket → `ws://localhost:3018/ws/device` → Headers: `Authorization: Bearer 1234` และ `X-Device-Id: BOX-0001` → Connect แล้วส่ง

```json
{ "type": "HELLO", "device_id": "BOX-0001", "hardware_model": "ESP32-DEVKIT-V1",
  "firmware_version": "1.0.0", "schema_version": 1, "config_version": 0, "boot_id": "test-1" }
```
จะได้ `WELCOME` และคำสั่งที่ค้างอยู่ (`COMMAND`) กลับมา
